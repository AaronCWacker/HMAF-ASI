### Working definitions and editorial choices

| 🧭 Label | 📐 Meaning in this presentation |
|---|---|
| FDE | Forward deployed engineer: a mentor who works with users to turn domain needs into usable systems. |
| Progressive longitudinal intelligence | Your framework for accumulating evidence, revising context, preserving lineage, and testing whether later decisions improve. It can operate through external memory without retraining model weights. |
| Distributed hive mind | Your metaphor for specialist agents coordinating through attributed memory, bounded tools, explicit ownership, and arbitration. It remains a hypothesis to compare with simpler workflows. |
| VBFs | The intended expansion was not found in the available history. This draft uses the working label **value/benefit factors**; retain the acronym only after defining it for your audience. |
| AI sets | Your working term for related models, assets, memories, and evaluations grouped around a capability or use case. |
| Language precedence | Project artifact authority and investment in useful keywords/file types. It does not establish a universal ranking of languages or override a system’s instruction/security hierarchy. |
| AIOps / LLMOps | AIOps commonly means AI applied to IT operations. MLOps means machine-learning operations; LLMOps means large-language-model operations. These practices support operating AI applications. This talk covers both and names the boundary in each example. |
| Evidence levels | Keep mentor experience, working hypotheses, documented implementation support, benchmark findings, and measured care outcomes distinguishable. |

Care claims should name the population, baseline, metric, and observation period. **Research anchors worth expanding in speaker notes:**

- **Care and value:** HealthBench evaluates healthcare response quality with rubrics; Sequential Diagnosis studies diagnostic reasoning and workup cost. Neither substitutes for measuring a deployed care pathway.
- **Development speed:** the experienced-developer productivity study and Cursor quality/velocity study make the distinction between perceived speed, local coding speed, and sustained delivery value teachable. Their results have specific tool, task, population, and time boundaries.
- **Specifications:** Evaluating AGENTS.md is a useful counterweight. Its inspected revision does not find a general benefit from repository context files and reports higher average inference cost. Treat useful context as something to qualify.
- **Memory:** A-MEM, Mem0, SimpleMem, and Agentic Context Engineering provide related mechanisms. Your Memory Loom demonstration uses lexical recall, while Chroma introduces a different retrieval implementation.
- **Single-file work:** The Single-File Test, by Diego Cabezas Palacios, evaluates first-output HTML generation with prompt adherence, functional correctness, and UI quality. Its observational design and limited scoring setup bound the conclusions.
- **Hive minds:** Why Do Multi-Agent LLM Systems Fail? supports testing design, alignment, verification, and termination failures. Collaborative Memory is relevant to attributed, controlled sharing.
- **Protocol and model snapshots:** the 2025 interoperability survey and Gemini 2.5 report remain useful dated readings. They do not establish today’s capabilities across every product or model family.

## 4. 🪄 First Principles and Copyable Prompts

These are reusable starting prompts for future demonstrations. Read each word set from left to right: **one word → two words → three words**. The extra words narrow the task. Replace bracketed inputs, add the preamble, and paste the selected prompt into an AI coding or authoring tool.

The principle is to **remove a part only when the remaining design preserves the required behavior**. Fewer components can reduce handoffs and failure points, but can also concentrate load, couple responsibilities, or weaken isolation. Count components and process steps; measure accepted quality, latency, cost, and recovery. A smaller implementation does not by itself prove a better asymptotic complexity or a speedup. A complexity claim needs a defined input size and an argument about how resource use grows with it.

### Universal preamble

```text
Use the supplied evidence, constraints, and acceptance checks. Produce the complete requested output with the smallest design that satisfies them. State assumptions, preserve provenance, and label mocks or missing inputs. Use synthetic healthcare examples. Report what you actually verified and the main unresolved tradeoff.
```

### Revision discipline

Update a card when evidence changes; preserve its stable ID and original topic mapping. Record what changed, why, which source supports it, and what needs rechecking. Requalify a demonstration after a material model, prompt, retrieval, memory, dependency, browser, or infrastructure change.

The shortest useful teaching pattern is **Intent → Evidence → Action → Check**. Use it as a small recurring cue across the presentation; keep the fuller context in the linked memory map.
